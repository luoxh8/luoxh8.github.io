Redis 缓存实战

缓存能扛住大部分读流量，但用不好会引入穿透、击穿、雪崩和一致性问题

📅 2026-08-07⏱ 2 分钟阅读🗄️ 数据库与中间件

缓存能扛住大部分读流量，但用不好会引入穿透、击穿、雪崩和一致性问题。

基本用法

@Service
public class ProductService {
    @Autowired
    private StringRedisTemplate redis;

    public Product getById(Long id) {
        String key = "product:" + id;
        String cached = redis.opsForValue().get(key);
        if (cached != null) {
            return JSON.parseObject(cached, Product.class);
        }
        Product product = productMapper.selectById(id);
        if (product != null) {
            redis.opsForValue().set(key, JSON.toJSONString(product), 30, TimeUnit.MINUTES);
        }
        return product;
    }
}

缓存穿透

查询不存在的 key，请求直接打到数据库：

解决方案：

  1. 缓存空值：不存在的也缓存，设置短过期
if (product == null) {
    redis.opsForValue().set(key, "", 2, TimeUnit.MINUTES);
}
  1. 布隆过滤器：先判断 key 是否可能存在

缓存击穿

热点 key 过期瞬间，大量请求同时打到数据库：

解决方案：互斥锁重建缓存

String lockKey = "lock:" + key;
if (redis.opsForValue().setIfAbsent(lockKey, "1", 10, TimeUnit.SECONDS)) {
    try {
        // 查库并重建缓存
    } finally {
        redis.delete(lockKey);
    }
} else {
    // 没拿到锁，短暂等待后重试
    Thread.sleep(50);
}

缓存雪崩

大量 key 同时过期，数据库被打垮：

解决方案：

  1. 过期时间加随机值
int ttl = 30 * 60 + ThreadLocalRandom.current().nextInt(300);
redis.opsForValue().set(key, value, ttl, TimeUnit.SECONDS);
  1. 多级缓存（本地 + Redis）
  2. 限流降级

缓存一致性

更新策略取舍：

  • Cache Aside：先更新数据库，再删缓存
@Transactional
public void update(Product product) {
    productMapper.updateById(product);
    redis.delete("product:" + product.getId());
}
  • 允许短暂不一致的业务，删除缓存即可
  • 严格要求一致的，用消息队列或 CDC 订阅 binlog 刷新缓存

总结

  • 穿透：缓存空值 / 布隆过滤器
  • 击穿：互斥锁重建
  • 雪崩：过期时间加随机值、多级缓存
  • 更新：先 DB 后删缓存
