MQTT 消息协议实战

MQTT 是物联网场景最常用的轻量消息协议，基于发布/订阅模型，适合低带宽、不稳定网络

📅 2022-04-09⏱ 2 分钟阅读⚙️ 后端与DevOps

MQTT 是物联网场景最常用的轻量消息协议，基于发布/订阅模型，适合低带宽、不稳定网络。

核心概念

  • Broker：消息服务器（如 EMQX、Mosquitto）
  • 主题 Topic：消息分类的层级路径，如 device/1001/command
  • QoS：消息投递质量
QoS 语义
0 最多一次，可能丢
1 至少一次，可能重复
2 恰好一次，最可靠

搭建 Broker

docker run -d -p 1883:1883 -p 18083:18083 \
  --name emqx emqx/emqx:latest

Web 控制台：http://服务器:18083（admin/public）。

Python 发布订阅

pip install paho-mqtt

订阅端：

import paho.mqtt.client as mqtt

def on_connect(client, userdata, flags, rc):
    print('connected')
    client.subscribe('device/+/command', qos=1)

def on_message(client, userdata, msg):
    print(f'{msg.topic}: {msg.payload.decode()}')

client = mqtt.Client()
client.on_connect = on_connect
client.on_message = on_message
client.connect('127.0.0.1', 1883)
client.loop_forever()

发布端（下发命令到设备）：

import paho.mqtt.client as mqtt

client = mqtt.Client()
client.connect('127.0.0.1', 1883)

# 向设备 1001 下发重启指令
client.publish('device/1001/command', '{"action":"reboot"}', qos=1)
client.disconnect()

Java 集成

<dependency>
    <groupId>org.eclipse.paho</groupId>
    <artifactId>org.eclipse.paho.client.mqttv3</artifactId>
    <version>1.2.5</version>
</dependency>
MqttClient client = new MqttClient("tcp://127.0.0.1:1883", "server-1");
MqttConnectOptions options = new MqttConnectOptions();
options.setCleanSession(true);
options.setAutomaticReconnect(true);
client.connect(options);

// 订阅设备上报
client.subscribe("device/+/report", (topic, message) -> {
    System.out.println(topic + ": " + new String(message.getPayload()));
});

// 下发命令
client.publish("device/1001/command",
        "{\"action\":\"reboot\"}".getBytes(), 1, false);

主题通配符

  • +：匹配单层，如 device/+/report
  • #：匹配多层，如 device/#

保留消息与遗嘱

# 保留消息：新订阅者也能立刻收到最后一条
client.publish('device/1001/status', 'online', retain=True)

# 遗嘱：设备异常断开时 Broker 自动发布
client.will_set('device/1001/status', 'offline', qos=1, retain=True)

总结

  • 发布/订阅 + 主题通配符，设备与服务器解耦
  • 下发指令用 QoS 1，控制类消息建议 retain
  • 上线记得断线重连
