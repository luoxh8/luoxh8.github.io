MySQL 索引详解

索引是 MySQL 性能的核心

📅 2026-08-07⏱ 2 分钟阅读🗄️ 数据库与中间件

索引是 MySQL 性能的核心。没有索引，查询就是全表扫描。

索引类型

类型 说明
主键索引 每张表一个，唯一且非空
唯一索引 值唯一，允许 NULL
普通索引 加速查询
联合索引 多个列的组合索引
全文索引 文本搜索 
CREATE INDEX idx_name ON user(name);
CREATE UNIQUE INDEX uk_email ON user(email);
CREATE INDEX idx_name_age ON user(name, age);  -- 联合索引

B+ 树原理

InnoDB 使用 B+ 树存储索引：

  • 叶子节点存数据/主键，按序排列
  • 非叶子节点只存索引键，扇出大、树矮
  • 范围查询高效：叶子节点有链表

聚簇索引（主键）的叶子节点就是数据行，二级索引叶子节点存主键值，查询需要回表。

explain 分析

EXPLAIN SELECT * FROM user WHERE name = 'luoxh';

重点看几列：

列 含义
type 访问类型，const > ref > range > index > all
key 实际使用的索引
rows 扫描行数（越小越好）
Extra 出现 Using filesort/Using temporary 需要优化

全表扫描 type=ALL 且行数大时，一定要建索引。

索引失效场景

-- 对索引列做函数运算，索引失效
SELECT * FROM user WHERE YEAR(create_time) = 2026;
-- 应改为范围查询
SELECT * FROM user WHERE create_time >= '2026-01-01' AND create_time < '2027-01-01';

-- 隐式类型转换，索引失效
SELECT * FROM user WHERE phone = 13800000000;  -- phone 是 varchar

-- 联合索引不满足最左前缀
SELECT * FROM user WHERE age = 20;  -- 联合索引是 (name, age)

-- LIKE 前置通配符
SELECT * FROM user WHERE name LIKE '%luoxh%';

覆盖索引

查询的列都在索引里，无需回表：

-- 联合索引 (status, create_time)，查询这两列直接走索引
SELECT status, create_time FROM order_table WHERE status = 1;

总结

  • 高频查询列、WHERE/JOIN/ORDER BY 列适合建索引
  • 用 EXPLAIN 验证是否走索引
  • 索引不是越多越好，写入会变慢
