MySQL 事务与隔离级别

事务保证一组操作要么全部成功、要么全部回滚，是数据一致性的基础

📅 2026-08-07⏱ 2 分钟阅读🗄️ 数据库与中间件

事务保证一组操作要么全部成功、要么全部回滚，是数据一致性的基础。

ACID

特性 含义
原子性 Atomicity 全部成功或全部回滚
一致性 Consistency 事务前后数据状态一致
隔离性 Isolation 事务之间互不干扰
持久性 Durability 提交后永久保存

隔离级别

-- 查看/设置隔离级别
SELECT @@transaction_isolation;
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
隔离级别 脏读 不可重复读 幻读
READ UNCOMMITTED 有 有 有
READ COMMITTED 无 有 有
REPEATABLE READ（默认） 无 无 有
SERIALIZABLE 无 无 无
  • 脏读：读到其他事务未提交的数据
  • 不可重复读：同一查询两次结果不一致（行被改）
  • 幻读：同一查询两次结果行数不一致（插入/删除）

事务操作

START TRANSACTION;

UPDATE account SET balance = balance - 100 WHERE id = 1;
UPDATE account SET balance = balance + 100 WHERE id = 2;

COMMIT;      -- 提交
ROLLBACK;    -- 回滚

MVCC 与锁

InnoDB 通过 MVCC（多版本并发控制）实现读写不互斥：

  • 每行有隐藏版本链（trx_id、roll_pointer）
  • 读操作通过 ReadView 看快照
  • 写操作加锁：行锁、间隙锁、临键锁

悲观锁与乐观锁

-- 悲观锁：SELECT ... FOR UPDATE 锁住行
SELECT * FROM stock WHERE id = 1 FOR UPDATE;

-- 乐观锁：用版本号判断
UPDATE stock SET count = count - 1, version = version + 1
WHERE id = 1 AND version = 5;

死锁

两个事务互相持有对方需要的锁就会死锁，InnoDB 会自动检测并回滚其中一个。避免死锁：

  • 按固定顺序访问资源
  • 事务尽量短
  • 用索引缩小锁范围

总结

  • 默认 REPEATABLE READ 已够用，别乱调 SERIALIZABLE
  • 转账等场景先锁后查，或用乐观锁
  • 事务要短平快，避免长事务
