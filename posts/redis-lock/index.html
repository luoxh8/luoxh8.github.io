Redis 分布式锁

多实例部署后， synchronized 只锁住单机

📅 2022-02-18⏱ 2 分钟阅读🗄️ 数据库与中间件

多实例部署后，synchronized 只锁住单机。分布式锁让多个节点互斥执行关键代码。

最简实现：SETNX

// 加锁：key 不存在才成功，带过期时间防止死锁
Boolean locked = redis.opsForValue()
        .setIfAbsent(lockKey, token, 30, TimeUnit.SECONDS);

if (Boolean.TRUE.equals(locked)) {
    try {
        // 业务逻辑
    } finally {
        // 释放锁
        redis.delete(lockKey);
    }
}

防误删：加锁标识

只用 delete 可能误删别人的锁（A 的锁过期后 B 拿到锁，A 释放时把 B 的锁删了）。用 Lua 脚本保证判断与删除的原子性：

String script = "if redis.call('get', KEYS[1]) == ARGV[1] " +
                "then return redis.call('del', KEYS[1]) " +
                "else return 0 end";

redis.execute(new DefaultRedisScript<>(script, Long.class),
        Collections.singletonList(lockKey), token);

Redisson 实现

生产环境直接用 Redisson，自带看门狗自动续期：

<dependency>
    <groupId>org.redisson</groupId>
    <artifactId>redisson-spring-boot-starter</artifactId>
    <version>3.35.0</version>
</dependency>
@Autowired
private RedissonClient redisson;

public void deductStock(Long skuId) {
    RLock lock = redisson.getLock("stock:" + skuId);
    try {
        // 尝试加锁，最多等 3 秒
        if (lock.tryLock(3, 30, TimeUnit.SECONDS)) {
            // 扣库存
        }
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    } finally {
        if (lock.isHeldByCurrentThread()) {
            lock.unlock();
        }
    }
}

Redisson 的看门狗会每 10 秒续期一次（默认 30 秒），业务没跑完锁不会提前过期。

锁的粒度

锁尽量细化：

// 粗：整单锁
redisson.getLock("order:" + orderId);

// 细：按商品锁，不同商品互不阻塞
redisson.getLock("stock:" + skuId);

可靠性注意

  • 加锁必须带过期时间，防止进程崩溃导致死锁
  • 释放锁要校验持有者（Lua 脚本）
  • 主从切换场景建议 RedLock 或引入中间件，普通业务 Redisson 单主即可

总结

  • 核心是 SETNX + 过期时间 + Lua 原子释放
  • Redisson 省心，自带续期与重入
  • 锁粒度越细并发越高
