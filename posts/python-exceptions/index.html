Python 异常处理最佳实践

异常处理写得好不好，直接决定程序在真实环境中的稳定性

📅 2020-04-02⏱ 1 分钟阅读🐍 Python

异常处理写得好不好，直接决定程序在真实环境中的稳定性。

基本语法

try:
    result = 10 / int('0')
except ZeroDivisionError:
    print('除数不能为 0')
except ValueError as e:
    print('类型错误', e)
else:
    print('没有异常时执行', result)
finally:
    print('无论如何都会执行')
  • try：可能出错的代码
  • except：捕获指定异常，可以有多个
  • else：没有异常时执行
  • finally：无论是否异常都执行（释放资源）

捕获异常的粒度

不要用裸 except: 吞掉所有异常，应该精确捕获：

# 不好：掩盖了所有错误，包括 KeyboardInterrupt
try:
    do_something()
except:
    pass

# 好：明确捕获预期异常，其他异常继续抛出
try:
    do_something()
except (ConnectionError, TimeoutError) as e:
    logger.warning('网络异常: %s', e)

自定义异常

业务代码中定义自己的异常，让调用方可以精确处理：

class BizError(Exception):
    """业务异常基类"""
    def __init__(self, code, message):
        super().__init__(message)
        self.code = code
        self.message = message

class UserNotExistError(BizError):
    pass

def get_user(uid):
    user = db.query(uid)
    if not user:
        raise UserNotExistError(404, f'用户 {uid} 不存在')
    return user

try:
    get_user(100)
except UserNotExistError as e:
    print(e.code, e.message)

结合日志

异常要记录完整堆栈，方便排查：

import logging

logging.basicConfig(level=logging.INFO)

try:
    risky_call()
except Exception:
    logging.exception('调用失败')  # 自动带上堆栈

注意 return 与 finally

finally 中的 return 会覆盖 try 中的返回值，尽量避免：

def f():
    try:
        return 1
    finally:
        return 2  # 返回 2！

总结

  • 精确捕获、必要时向上抛
  • 用自定义异常表达业务语义
  • 用 logging.exception 保留堆栈
  • finally 里不要写 return
