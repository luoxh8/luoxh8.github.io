Spring Boot 集成 RabbitMQ

Spring Boot 让 RabbitMQ 的使用变得非常简单：注解声明、模板发送、监听消费

📅 2023-05-08⏱ 1 分钟阅读🗄️ 数据库与中间件

Spring Boot 让 RabbitMQ 的使用变得非常简单：注解声明、模板发送、监听消费。

引入依赖

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-amqp</artifactId>
</dependency>
spring:
  rabbitmq:
    host: localhost
    port: 5672
    username: guest
    password: guest
    listener:
      simple:
        acknowledge-mode: manual   # 手动确认
        prefetch: 10

声明交换机与队列

@Configuration
public class RabbitConfig {

    public static final String EXCHANGE = "order.exchange";
    public static final String QUEUE = "order.queue";
    public static final String ROUTING_KEY = "order.create";

    @Bean
    public DirectExchange orderExchange() {
        return new DirectExchange(EXCHANGE, true, false);
    }

    @Bean
    public Queue orderQueue() {
        return QueueBuilder.durable(QUEUE).build();
    }

    @Bean
    public Binding binding() {
        return BindingBuilder.bind(orderQueue())
                .to(orderExchange())
                .with(ROUTING_KEY);
    }
}

发送消息

@Service
public class OrderProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void sendCreateOrder(Order order) {
        rabbitTemplate.convertAndSend(
                RabbitConfig.EXCHANGE,
                RabbitConfig.ROUTING_KEY,
                order
        );
    }
}

消费消息

@Component
public class OrderConsumer {

    @RabbitListener(queues = RabbitConfig.QUEUE)
    public void handle(Order order, Channel channel,
                       @Header(AmqpHeaders.DELIVERY_TAG) long tag) throws IOException {
        try {
            // 处理订单：写库、发通知
            channel.basicAck(tag, false);
        } catch (Exception e) {
            // 失败重试，超过次数进死信队列
            channel.basicNack(tag, false, true);
        }
    }
}

重试与死信

spring:
  rabbitmq:
    listener:
      simple:
        retry:
          enabled: true
          max-attempts: 3
          initial-interval: 2s

消费失败多次后消息进入死信队列，便于人工排查。

幂等消费

消息可能重复投递，消费端要幂等：

// 用消息 ID 或业务 ID 去重
if (redis.opsForValue().setIfAbsent("order:done:" + order.getId(), "1",
        24, TimeUnit.HOURS)) {
    // 首次处理
}

总结

  • 注解声明交换机/队列，配置即代码
  • 手动 ack + 重试 + 死信队列是生产标配
  • 消费端必须幂等
