Docker Compose 编排

一个项目往往有多个服务：应用、MySQL、Redis、Nginx

📅 2026-08-07⏱ 1 分钟阅读⚙️ 后端与DevOps

一个项目往往有多个服务：应用、MySQL、Redis、Nginx。Docker Compose 用一份配置文件编排它们，一条命令全部启动。

示例配置

version: "3.8"

services:
  app:
    build: .
    ports:
      - "8080:8080"
    depends_on:
      - mysql
      - redis
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/demo
      SPRING_REDIS_HOST: redis
    restart: always

  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: 123456
      MYSQL_DATABASE: demo
    volumes:
      - mysql_data:/var/lib/mysql
    ports:
      - "3306:3306"

  redis:
    image: redis:7-alpine
    volumes:
      - redis_data:/data
    restart: always

volumes:
  mysql_data:
  redis_data:

容器之间通过服务名互相访问（如 mysql:3306）。

常用命令

docker compose up -d               # 后台启动
docker compose up -d --build       # 重新构建并启动
docker compose ps                  # 查看状态
docker compose logs -f app         # 跟踪某个服务日志
docker compose down                # 停止并删除容器
docker compose down -v             # 连数据卷一起删除（慎用）
docker compose restart             # 重启
docker compose exec app bash       # 进入容器

环境变量文件

敏感配置放 .env：

MYSQL_ROOT_PASSWORD=xxxxx
APP_PORT=8080
services:
  app:
    environment:
      APP_PORT: ${APP_PORT}
      MYSQL_PASSWORD: ${MYSQL_ROOT_PASSWORD}

健康检查

services:
  app:
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/actuator/health"]
      interval: 30s
      timeout: 5s
      retries: 3

生产注意

  • 数据卷持久化，down -v 会丢数据
  • 日志限制大小：
logging:
  driver: json-file
  options:
    max-size: "20m"
    max-file: "5"
  • 敏感信息走 .env 或密钥管理，不要写进 compose 文件提交仓库

总结

  • Compose 适合单机多容器编排
  • 服务名互通 + 数据卷持久化是核心
  • 生产环境注意日志与安全配置
