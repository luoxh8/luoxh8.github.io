Jenkins 自动构建发布

CI/CD 让发布从手动操作变成自动流程：代码提交 → 自动构建 → 自动部署

📅 2026-08-07⏱ 1 分钟阅读⚙️ 后端与DevOps

CI/CD 让发布从手动操作变成自动流程：代码提交 → 自动构建 → 自动部署。

Jenkins 安装

docker run -d \
  --name jenkins \
  -p 8080:8080 \
  -v jenkins_home:/var/jenkins_home \
  -v /var/run/docker.sock:/var/run/docker.sock \
  jenkins/jenkins:lts

首次访问 http://服务器:8080，用初始密码解锁：

docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword

Pipeline 脚本

pipeline {
    agent any

    environment {
        APP_NAME = 'demo'
        SERVER = '192.168.1.20'
    }

    stages {
        stage('拉取代码') {
            steps { checkout scm }
        }

        stage('构建') {
            steps {
                sh 'mvn clean package -DskipTests'
            }
        }

        stage('构建镜像') {
            steps {
                sh 'docker build -t demo:${BUILD_NUMBER} .'
            }
        }

        stage('部署') {
            steps {
                sh '''
                    scp target/demo.jar root@${SERVER}:/opt/demo/
                    ssh root@${SERVER} "cd /opt/demo && docker compose up -d --build"
                '''
            }
        }
    }
}

Webhook 触发

在 GitHub 仓库 Settings → Webhooks 添加：

URL: http://jenkins.example.com/github-webhook/
Content type: application/json

Jenkins 任务勾选 “GitHub hook trigger for GITScm polling”，之后每次 push 自动触发。

参数化构建

允许手动选择分支或环境：

parameters {
    choice(name: 'ENV', choices: ['dev', 'prod'], description: '环境')
    string(name: 'TAG', defaultValue: 'latest', description: '镜像标签')
}

stage('部署') {
    steps {
        sh "ssh root@server 'cd /opt/${params.ENV} && docker compose up -d'"
    }
}

邮件通知

post {
    failure {
        emailext(
            subject: "构建失败: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
            body: "请查看构建日志",
            to: "dev@example.com"
        )
    }
}

总结

  • Pipeline 用代码描述构建流程，可版本化
  • Webhook 实现提交即触发
  • 失败通知 + 构建产物归档是标配
