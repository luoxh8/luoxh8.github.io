RESTful 接口设计规范

RESTful 是一套基于 HTTP 语义的接口设计风格，遵循它可以让 API 易读、易维护

📅 2020-07-02⏱ 2 分钟阅读☕ Java

RESTful 是一套基于 HTTP 语义的接口设计风格，遵循它可以让 API 易读、易维护。

URL 与资源命名

用名词复数表示资源，用 HTTP 方法表示操作：

方法 URL 语义
GET /api/users 获取用户列表
GET /api/users/1 获取单个用户
POST /api/users 创建用户
PUT /api/users/1 全量更新用户
PATCH /api/users/1 部分更新用户
DELETE /api/users/1 删除用户

子资源用嵌套：GET /api/users/1/orders 获取用户的订单。

避免动词化 URL：/api/getUser、/api/deleteUser 都是反面教材。

查询参数

列表接口支持过滤、分页、排序：

GET /api/users?page=1&size=20&sort=createdAt,desc&status=active
@GetMapping("/users")
public Page<User> list(
        @RequestParam(defaultValue = "1") int page,
        @RequestParam(defaultValue = "20") int size) {
    return userService.page(page, size);
}

状态码语义

状态码 含义 场景
200 成功 查询、更新成功
201 已创建 创建资源成功
204 无内容 删除成功
400 参数错误 请求参数不合法
401 未认证 未登录或 token 失效
403 无权限 权限不足
404 不存在 资源不存在
500 服务器错误 未捕获异常

统一响应体

{
  "code": 0,
  "message": "success",
  "data": { "id": 1, "name": "luoxh" }
}
public record ApiResult<T>(int code, String message, T data) {
    public static <T> ApiResult<T> ok(T data) {
        return new ApiResult<>(0, "success", data);
    }
    public static <T> ApiResult<T> error(int code, String message) {
        return new ApiResult<>(code, message, null);
    }
}

全局异常处理

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(IllegalArgumentException.class)
    public ApiResult<Void> handleBadRequest(IllegalArgumentException e) {
        return ApiResult.error(400, e.getMessage());
    }

    @ExceptionHandler(Exception.class)
    public ApiResult<Void> handleOther(Exception e) {
        return ApiResult.error(500, "服务器内部错误");
    }
}

总结

  • 资源用名词复数，操作用 HTTP 方法表达
  • 状态码要准确，错误信息要可读
  • 统一响应体 + 全局异常处理，前后端协作更顺畅
