Git 分支管理

分支是 Git 最强大的特性，让多人并行开发互不干扰

📅 2019-06-11⏱ 1 分钟阅读🛠️ 开发工具

分支是 Git 最强大的特性，让多人并行开发互不干扰。

基础操作

git branch              # 查看本地分支
git branch -a           # 查看所有分支（含远程）
git branch feature-x    # 创建分支
git checkout feature-x  # 切换分支
git switch feature-x    # 切换分支（新写法）
git checkout -b feature-x  # 创建并切换
git branch -d feature-x    # 删除已合并的分支

合并与冲突

git checkout main
git merge feature-x

冲突时 Git 会标记冲突文件：

<<<<<<< HEAD
你的代码
=======
对方代码
>>>>>>> feature-x

手动修改后：

git add conflicted-file
git commit

rebase 与 merge

# merge：保留分叉历史
git merge feature-x

# rebase：线性历史，更干净
git rebase main

rebase 会把当前分支的提交“挪”到目标分支顶端，适合整理本地提交；不要对已推送的分支做 rebase。

常用的分支模型

简单模型（小团队）

main（稳定）
  └── feature/xxx（功能分支）
  └── fix/xxx（修复分支）

Git Flow（中大型项目）

master（发布）
develop（开发主干）
  ├── feature/*
  ├── release/*
  └── hotfix/*

撤销分支上的操作

git reset --soft HEAD~1    # 撤销提交但保留改动
git reset --hard HEAD~1    # 彻底撤销（慎用）
git revert <commit>        # 生成反向提交，适合已推送

总结

  • 功能分支 + 合并，保持 main 可发布
  • 冲突不可避免，耐心解决即可
  • 已推送的分支用 revert，别用 reset
