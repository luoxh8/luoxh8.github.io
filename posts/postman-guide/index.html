Postman 接口测试

Postman 是最常用的 API 调试工具，从手动调试到自动化测试都离不开

📅 2022-12-10⏱ 1 分钟阅读🛠️ 开发工具

Postman 是最常用的 API 调试工具，从手动调试到自动化测试都离不开。

基础用法

选择方法、填 URL、带参数、点 Send：

GET  https://api.example.com/users?page=1
POST https://api.example.com/login

Body 选 JSON：

{ "username": "luoxh", "password": "***" }

环境变量

开发、测试、生产环境地址不同，用环境变量管理：

{{base_url}}/users

在 Environments 里定义：

{ "base_url": "https://dev-api.example.com" }

常用内置变量：

{{$timestamp}}       // 当前时间戳
{{$guid}}            // 随机 GUID
{{$randomInt}}       // 随机整数

脚本：Tests

登录后自动保存 token，后续请求直接使用：

// 登录接口 Tests
const res = pm.response.json();
pm.test('登录成功', () => pm.expect(res.code).to.eql(0));
pm.environment.set('token', res.data.token);

其他接口 Header 用 Authorization: Bearer {{token}}。

断言常用写法

pm.test('状态码 200', () => pm.response.to.have.status(200));
pm.test('响应时间', () => pm.expect(pm.response.responseTime).to.be.below(500));
pm.test('字段存在', () => pm.expect(pm.response.json().data.id).to.exist);
pm.test('数组长度', () => pm.expect(pm.response.json().data.list).to.have.lengthOf(10));

集合与自动化

把相关接口放进 Collection，用 Collection Runner 批量执行：

# 命令行运行集合
newman run MyCollection.json -e DevEnv.json
newman run MyCollection.json -e DevEnv.json --reporters cli,json

CI 里集成 Newman，接口回归自动化：

npx newman run collection.json -e env.json --bail

总结

  • 环境变量 + token 传递，一套用例跑多个环境
  • Tests 断言让调试变回归测试
  • Newman 接入 CI 实现接口自动化
