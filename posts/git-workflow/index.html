Git 协作工作流

规范的工作流能让团队少踩很多坑

📅 2026-08-07⏱ 1 分钟阅读🛠️ 开发工具

代码写得好，协作更要顺。规范的工作流能让团队少踩很多坑。

提交信息规范

推荐 Conventional Commits 格式：

<type>(<scope>): <subject>
feat: 新增用户登录接口
fix: 修复订单金额精度问题
docs: 更新接口文档
refactor: 重构缓存模块
test: 补充单元测试
chore: 升级依赖版本

好的提交信息让人能快速浏览历史：

git log --oneline
# feat: 新增用户登录接口
# fix: 修复订单金额精度问题

分支命名

feature/user-login
fix/order-amount
hotfix/payment-timeout
docs/readme-update

提交流程

git pull --rebase        # 先同步远端，避免合并提交
git add .
git commit -m "feat: xxx"
git push origin feature/user-login

提交前自查：

git status              # 确认没有误加文件
git diff                # 检查改动内容

Pull Request 流程

  1. 从 main 切出 feature/xxx
  2. 开发并提交，push 到远端
  3. 发起 PR，描述改动与测试情况
  4. 至少一人 Review，通过后合并

Code Review 要点

  • 先看整体设计，再抠细节
  • 关注安全问题（SQL 注入、越权、敏感信息）
  • 关注边界条件（空值、超时、并发）
  • 评论要具体、给建议，别只说“不对”

保护分支

在 GitHub Settings → Branches 设置 main 分支保护：

  • 要求 PR 才能合并
  • 至少 1 个 review
  • 合并且通过 CI

总结

  • 提交信息规范、分支命名清晰
  • 提交前先 pull –rebase
  • PR + Review + CI 是质量三道闸
