Java 线程池详解

每次任务都 new Thread 很浪费资源

📅 2026-08-07⏱ 2 分钟阅读☕ Java

每次任务都 new Thread 很浪费资源。线程池复用线程，还能控制并发量。

核心参数

ThreadPoolExecutor pool = new ThreadPoolExecutor(
    2,                          // corePoolSize 核心线程数
    4,                          // maximumPoolSize 最大线程数
    60, TimeUnit.SECONDS,       // 空闲线程存活时间
    new LinkedBlockingQueue<>(100),  // 任务队列
    new ThreadPoolExecutor.CallerRunsPolicy()  // 拒绝策略
);

执行流程：

  1. 线程数 < 核心线程数 → 创建新线程执行
  2. 线程数 ≥ 核心线程数 → 任务进队列
  3. 队列满 → 创建新线程直到最大线程数
  4. 还是满 → 执行拒绝策略

拒绝策略

策略 行为
AbortPolicy 抛异常（默认）
CallerRunsPolicy 调用线程自己执行
DiscardPolicy 静默丢弃
DiscardOldestPolicy 丢弃最旧任务

生产环境推荐 CallerRunsPolicy，不会丢任务也不会压垮系统。

Executors 工具类

Executors.newFixedThreadPool(4);     // 固定线程数
Executors.newCachedThreadPool();     // 弹性线程池
Executors.newSingleThreadExecutor(); // 单线程
Executors.newScheduledThreadPool(2); // 定时任务

注意：newFixedThreadPool 和 newSingleThreadExecutor 使用无界队列，任务积压可能耗尽内存；推荐直接使用 ThreadPoolExecutor 构造器，明确参数。

实战：异步发邮件

@Configuration
public class ThreadPoolConfig {

    @Bean("mailExecutor")
    public ThreadPoolExecutor mailExecutor() {
        return new ThreadPoolExecutor(
            2, 4, 60, TimeUnit.SECONDS,
            new LinkedBlockingQueue<>(200),
            new ThreadPoolExecutor.CallerRunsPolicy()
        );
    }
}

@Service
public class MailService {
    @Resource
    private ThreadPoolExecutor mailExecutor;

    public void sendAsync(String to, String content) {
        mailExecutor.execute(() -> {
            // 发邮件逻辑
        });
    }
}

关闭线程池

pool.shutdown();                 // 等任务执行完再关闭
pool.shutdownNow();              // 立即关闭
pool.awaitTermination(30, TimeUnit.SECONDS);  // 等待结束

总结

  • 用 ThreadPoolExecutor 明确核心线程数、队列和拒绝策略
  • 避免无界队列
  • 项目结束时要优雅关闭线程池
