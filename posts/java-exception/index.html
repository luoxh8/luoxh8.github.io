Java 异常处理规范

异常处理的质量决定系统的稳定性与可排查性

📅 2026-08-07⏱ 2 分钟阅读☕ Java

异常处理的质量决定系统的稳定性与可排查性。

异常体系

Throwable
├── Error（系统级，如 OutOfMemoryError，不处理）
└── Exception
    ├── 受检异常 Checked（编译期要求处理，如 IOException）
    └── RuntimeException 非受检（运行期，如 NullPointerException）

try-catch-finally

try {
    InputStream in = new FileInputStream("a.txt");
    // 读取
} catch (FileNotFoundException e) {
    log.warn("文件不存在", e);
} catch (IOException e) {
    log.error("读取失败", e);
} finally {
    // 释放资源
}

try-with-resources

实现了 AutoCloseable 的资源自动关闭，代码更简洁：

try (InputStream in = new FileInputStream("a.txt");
     BufferedReader reader = new BufferedReader(new InputStreamReader(in))) {
    String line = reader.readLine();
} catch (IOException e) {
    log.error("读取失败", e);
}

自定义异常

public class BizException extends RuntimeException {
    private final int code;

    public BizException(int code, String message) {
        super(message);
        this.code = code;
    }

    public int getCode() {
        return code;
    }
}

业务异常继承 RuntimeException，不需要到处声明 throws：

public User getById(Long id) {
    User user = userMapper.selectById(id);
    if (user == null) {
        throw new BizException(404, "用户不存在");
    }
    return user;
}

不要吞异常

// 不好：异常被吞，排查无门
try {
    risky();
} catch (Exception e) {
}

// 好：记录日志或向上抛
try {
    risky();
} catch (Exception e) {
    log.error("risky 调用失败", e);
    throw new BizException(500, "调用失败");
}

保持异常链

包装异常时保留原始异常：

catch (SQLException e) {
    throw new BizException(500, "数据库错误", e);  // cause 传进去
}

总结

  • 资源用 try-with-resources 自动关闭
  • 业务异常继承 RuntimeException，配合全局处理器
  • 永远保留异常堆栈，别吞异常
