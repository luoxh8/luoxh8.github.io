数据库备份与恢复

没有备份的数据库，出事故只能祈祷

📅 2026-08-07⏱ 1 分钟阅读🗄️ 数据库与中间件

数据是命根子。没有备份的数据库，出事故只能祈祷。

MySQL 逻辑备份

# 备份整个库
mysqldump -uroot -p --single-transaction demo > demo.sql

# 只备份表结构
mysqldump -uroot -p --no-data demo > schema.sql

# 压缩备份
mysqldump -uroot -p --single-transaction demo | gzip > demo_$(date +%F).sql.gz

--single-transaction 保证备份期间数据一致，不锁表。

MySQL 恢复

mysql -uroot -p demo < demo.sql
gunzip -c demo_2026-08-07.sql.gz | mysql -uroot -p demo

MongoDB 备份

# 备份
mongodump --uri="mongodb://localhost:27017" -d demo -o /backup

# 恢复
mongorestore --uri="mongodb://localhost:27017" /backup/demo

定时备份脚本

#!/bin/bash
BACKUP_DIR=/backup/mysql
DATE=$(date +%F)
mkdir -p "$BACKUP_DIR"

mysqldump -uroot -p'密码' --single-transaction demo |
    gzip > "$BACKUP_DIR/demo_$DATE.sql.gz"

# 保留最近 7 天
find "$BACKUP_DIR" -name "*.sql.gz" -mtime +7 -delete

crontab 每天凌晨 2 点执行：

0 2 * * * /opt/scripts/backup-mysql.sh >> /var/log/backup.log 2>&1

备份策略

级别 频率 保留
全量备份 每天 7~30 天
增量/binlog 实时/每小时 按磁盘
异地备份 每天 长期

MySQL 主从本身不是备份，误删数据主从一起删。真正的保障是定时全量 + binlog 恢复。

恢复演练

备份不演练等于没备份。定期：

  1. 在测试库导入最新备份
  2. 验证数据完整性与业务可用
  3. 记录恢复耗时，评估 RTO/RPO

总结

  • 全量 + binlog/增量，异地存储
  • 备份脚本加日志和保留策略
  • 定期做恢复演练
