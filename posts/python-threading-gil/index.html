Python 多线程与 GIL 锁

Python 的 threading 模块用起来很方便，但很多初学者会发现：开多线程并没有让计算变快

📅 2021-06-30⏱ 2 分钟阅读🐍 Python

Python 的 threading 模块用起来很方便，但很多初学者会发现：开多线程并没有让计算变快。这就要说到 GIL。

GIL 是什么

GIL（Global Interpreter Lock）是 CPython 解释器中的全局锁，保证同一时刻只有一个线程在执行 Python 字节码。所以同一进程内的多线程无法真正并行利用多核 CPU。

CPU 密集与 IO 密集

import time
import threading

def cpu_work():
    total = 0
    for i in range(3_000_000):
        total += i
    return total

def io_work():
    time.sleep(1)  # 模拟 IO

# 多线程执行 CPU 密集任务：不会变快（受 GIL 限制）
threads = [threading.Thread(target=cpu_work) for _ in range(4)]
start = time.time()
[t.start() for t in threads]
[t.join() for t in threads]
print(f'CPU 密集多线程: {time.time() - start:.2f}s')

# 多线程执行 IO 密集任务：显著变快（IO 时释放 GIL）
threads = [threading.Thread(target=io_work) for _ in range(4)]
start = time.time()
[t.start() for t in threads]
[t.join() for t in threads]
print(f'IO 密集多线程: {time.time() - start:.2f}s')

IO 操作（网络请求、文件读写、数据库查询）会释放 GIL，等待期间其他线程可以执行，因此多线程适合 IO 密集场景。

锁与线程安全

多个线程同时修改共享数据会出问题，需要使用锁：

import threading

counter = 0
lock = threading.Lock()

def add():
    global counter
    for _ in range(100_000):
        with lock:
            counter += 1

threads = [threading.Thread(target=add) for _ in range(4)]
[t.start() for t in threads]
[t.join() for t in threads]
print(counter)  # 400000

并发方案怎么选

场景 推荐方案
IO 密集、任务量中等 threading 多线程
IO 密集、任务量巨大 asyncio 协程
CPU 密集 multiprocessing 多进程
两者混合 concurrent.futures + 线程池/进程池 
from concurrent.futures import ThreadPoolExecutor

def fetch(url):
    return len(url)

with ThreadPoolExecutor(max_workers=4) as pool:
    results = pool.map(fetch, ['https://a.com'] * 10)
    print(list(results))

总结

  • GIL 让多线程无法并行执行 Python 代码，但 IO 密集场景仍值得用
  • 共享数据记得加锁
  • CPU 密集请用多进程，海量 IO 请用协程
