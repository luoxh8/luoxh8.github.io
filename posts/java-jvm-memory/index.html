JVM 内存模型与调优

理解 JVM 内存结构，才能定位 OOM、频繁 GC 等问题

📅 2026-08-07⏱ 2 分钟阅读☕ Java

理解 JVM 内存结构，才能定位 OOM、频繁 GC 等问题。

内存区域

区域 内容 是否线程共享
堆 Heap 对象实例、数组 共享
栈 Stack 局部变量、方法调用 线程私有
方法区 类信息、常量、静态变量 共享
程序计数器 字节码执行位置 线程私有
本地方法栈 native 方法 线程私有

堆的分代结构

堆
├── 新生代 Young
│   ├── Eden（新对象）
│   ├── Survivor0
│   └── Survivor1
└── 老年代 Old（存活多次的对象）

对象先在 Eden 分配，经过多次 Minor GC 仍存活的对象晋升到老年代。

常用 JVM 参数

java -Xms256m -Xmx512m -jar app.jar
参数 含义
-Xms 初始堆大小
-Xmx 最大堆大小
-Xss 线程栈大小
-XX:MaxMetaspaceSize 元空间上限
-XX:+PrintGCDetails 打印 GC 日志
-XX:SurvivorRatio=8 Eden:Survivor 比例

堆大小建议 -Xms 与 -Xmx 一致，避免运行时动态扩容。

查看内存状态

# 查看进程内存与 GC 情况
jps                    # 列出 Java 进程
jmap -heap <pid>       # 查看堆信息
jstat -gc <pid> 1000   # 每秒输出 GC 统计
jstack <pid>           # 线程快照

常见问题排查

OOM：Java heap space —— 堆内存不足：

java -Xmx1g -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/tmp/dump.hprof -jar app.jar

然后用 jvisualvm 或 MAT 分析 dump 文件，找出大对象。

CPU 飙高：

top -Hp <pid>           # 找出高 CPU 线程
jstack <pid>            # 转成线程栈，定位代码

总结

  • 对象在堆中分配，方法调用压栈
  • 合理设置 -Xms/-Xmx，开启 GC 日志
  • OOM 时保留堆 dump，用工具分析
