RabbitMQ 入门

RabbitMQ 是经典的消息中间件，用于解耦、异步、削峰

📅 2026-08-07⏱ 1 分钟阅读🗄️ 数据库与中间件

RabbitMQ 是经典的消息中间件，用于解耦、异步、削峰。

启动

docker run -d -p 5672:5672 -p 15672:15672 \
  --name rabbitmq rabbitmq:3-management

管理台：http://服务器:15672（guest/guest）。

核心概念

  • Producer：发送消息的一方
  • Consumer：接收消息的一方
  • Exchange：交换机，负责路由
  • Queue：队列，存储消息
  • Routing Key：路由键，决定消息去哪个队列

四种交换机

类型 路由规则
Direct 路由键完全匹配
Topic 路由键通配符匹配（* 单词、# 多词）
Fanout 广播给所有绑定队列
Headers 按消息头匹配

Python 发送与接收

pip install pika

发送：

import pika

conn = pika.BlockingConnection(pika.ConnectionParameters('localhost'))
ch = conn.channel()
ch.queue_declare(queue='order_queue', durable=True)

ch.basic_publish(
    exchange='',
    routing_key='order_queue',
    body='{"orderId": 1001}',
    properties=pika.BasicProperties(delivery_mode=2)  # 持久化
)
conn.close()

接收：

import pika

def callback(ch, method, properties, body):
    print('收到:', body)
    ch.basic_ack(delivery_tag=method.delivery_tag)  # 确认消息

conn = pika.BlockingConnection(pika.ConnectionParameters('localhost'))
ch = conn.channel()
ch.queue_declare(queue='order_queue', durable=True)
ch.basic_qos(prefetch_count=1)
ch.basic_consume(queue='order_queue', on_message_callback=callback)
ch.start_consuming()

消息确认

  • 自动确认：收到即删除，可能丢消息
  • 手动确认 ack：处理成功才确认，失败可以重新入队
ch.basic_ack(delivery_tag=method.delivery_tag)
# 或拒绝并重新入队
ch.basic_nack(delivery_tag=method.delivery_tag, requeue=True)

延迟队列

用死信队列（DLX）实现延迟消息：

args = {
    'x-dead-letter-exchange': 'dlx',
    'x-dead-letter-routing-key': 'delay_queue',
    'x-message-ttl': 60000  # 1 分钟延迟
}
ch.queue_declare(queue='delay_source', arguments=args)

总结

  • 解耦、异步、削峰是三大价值
  • 生产环境务必：队列持久化 + 手动 ack
  • 用管理台观察队列堆积情况
