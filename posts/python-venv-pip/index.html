Python 虚拟环境与依赖管理

不同项目依赖不同版本的库，混在一起迟早出问题

📅 2026-08-07⏱ 1 分钟阅读🐍 Python

不同项目依赖不同版本的库，混在一起迟早出问题。虚拟环境就是给每个项目一套独立的 Python 环境。

创建与激活

Python 3.3+ 自带 venv：

# 创建虚拟环境
python -m venv venv

# Windows 激活
venv\Scripts\activate

# macOS / Linux 激活
source venv/bin/activate

# 退出
deactivate

激活后，pip install 的包只装进当前环境，不会污染全局。

安装与导出依赖

# 安装指定版本
pip install django==4.2
pip install "requests>=2.31"

# 导出当前环境的依赖清单
pip freeze > requirements.txt

# 根据清单一键安装
pip install -r requirements.txt

requirements.txt 内容示例：

Django==4.2.11
requests==2.32.3
gunicorn==22.0.0

常见命令速查

pip list                 # 查看已安装的包
pip show django          # 查看某个包的信息
pip uninstall django     # 卸载
pip install -U pip       # 升级 pip 本身
pip config list          # 查看 pip 配置

配置国内镜像源

国内下载 PyPI 很慢，可以切换镜像：

pip install -i https://pypi.tuna.tsinghua.edu.cn/simple requests

# 永久生效
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

其他工具

  • poetry：更现代的依赖管理，自动解析依赖树，生成 pyproject.toml
  • pipenv：把虚拟环境与依赖管理合并，支持 Pipfile
  • conda：适合科学计算场景，可管理 Python 版本本身
# poetry 常用
poetry new myproject
poetry add requests
poetry run python main.py

总结

  • 每个项目都建独立虚拟环境
  • requirements.txt 进版本库，方便复现环境
  • 部署前用 pip freeze 锁定版本
